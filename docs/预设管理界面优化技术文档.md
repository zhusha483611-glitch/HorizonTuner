## 背景与目标

本次优化针对“多段式加速自定义预设”的管理体验，主要目标：

- 提升预设查找与操作效率：搜索、排序、列表/卡片双视图、详情预览、快捷键

- 提升稳定性：配置兼容性迁移与损坏配置备份
- 可验证：新增自动化单元测试与手工测试清单

## 数据结构变更（handling-auto.json）

配置文件位置：`%LocalAppData%\MA_FH5Trainer\handling-auto.json`

### VelocityPreset 新增字段

- `id`：预设唯一标识（string，Guid 文本）
- `useCount`：累计使用次数（int）
- `lastUsedTimeUtc`：最近一次使用时间（DateTime?，UTC）

说明：

- 旧配置无上述字段时会自动补齐，并在必要时回写一次配置文件。
- 使用 UTC 存储可避免时区变更导致的排序混乱；展示时统一转本地时间。

## 配置迁移与稳定性策略

### 迁移/归一化内容

入口：`HandlingAutoConfigManager.LoadInternal()` 读取后调用 `HandlingAutoConfigMigration.NormalizeConfig()`。

归一化规则：

- `CustomVelocityPresets == null` 时初始化为空列表
- `VelocityPreset.Id` 为空时生成新 Id
- `VelocityPreset.CreatedTime == default` 时补为 `DateTime.Now`
- `VelocityPreset.UseCount < 0` 时钳制为 0
- `VelocityPreset.LastUsedTimeUtc` 若被写成非 UTC Kind，按 UTC 解释；若明显未来时间（> nowUtc + 1 天），钳制为 nowUtc

### 损坏配置备份

当配置反序列化抛异常时：

- 记录 Debug 输出
- 将原文件移动或复制为：`handling-auto.json.corrupt.<yyyyMMddHHmmss>.bak`
- 返回默认 `HandlingAutoConfig`，保证应用可继续启动

## 热门度计算（HotScore）

热门度用于排序与展示，来源：

- `useCount`（越大越热）
- `lastUsedTimeUtc`（越新越热，随时间衰减）

实现位于：`PresetHotness.CalculateHotScore()`。

当前公式（0–100 分）：

- 基础分（随 useCount 饱和）：`base = 100 * (1 - exp(-useCount / 10))`
- 时间衰减（约每 3 天衰减到 ~1/2）：`decay = 1 / (1 + daysSinceLastUse / 3)`
- 最终：`hot = clamp(base * decay, 0, 100)`

设计意图：

- 避免 useCount 稍大就全部“顶格 100”导致无法区分
- 同 useCount 下，最近使用应更靠前
- 同时间下，useCount 更高应更靠前

## UI 与交互实现要点

### 信息架构

- 顶部：搜索（即时过滤）、排序下拉、列表/卡片切换、摘要统计
- 左侧：预设集合
  - 列表：表格列（名称/热度/使用次数/最近使用/创建时间）
  - 卡片：更直观展示热度与使用信息
- 右侧：详情面板
  - 热度与统计
  - 3 段曲线参数预览（Gamma/强度）
  - 核心操作按钮

### 快捷键与操作效率

- Enter：应用并关闭
- Ctrl+Enter：仅应用（窗口保持打开）
- F2：重命名
- Delete：删除
- Ctrl+F：聚焦搜索框
- 右键菜单：应用/应用并关闭/重命名/删除

### 统计写入点

当用户“应用预设”时（由 Handling 页面实际落地应用）：

- 调用 `VelocityPresetUsage.MarkUsed(preset, DateTime.UtcNow)`
- 然后保存 `_configStore.Save(config)`，保证统计持久化

对应入口：[ApplyCustomPreset](../MA_FH5Trainer/MA_FH5Trainer/Views/SubPages/SelfVehicle/Handling.Velocity.cs#L645-L687)

## 测试

### 自动化单元测试

测试项目：`HorizonTuner.Tests`（覆盖配置迁移/预设使用/热门度/转换器/节流/Handling 曲线）

覆盖点：

- 配置迁移归一化（Id 补齐、负数钳制、未来时间钳制、空列表修复）
- 预设使用统计更新（Id 补齐、useCount 增量、lastUsed 写入）
- 热门度计算（更近期/更多使用应更“热”）

运行方式：

```bash
dotnet test MA_FH5Trainer/HorizonTuner.sln --configuration Release
```

### 手工测试清单（功能/兼容/性能）

功能测试：

- 保存预设 → 打开管理窗口 → 搜索过滤 → 排序切换
- 列表/卡片切换是否保持选中项
- 详情面板参数与统计是否与选中项一致
- 应用（Enter/双击/右键）后：useCount +1、最近使用时间刷新、热门排序变化
- 重命名（F2/按钮/右键）：名称去重、统计不丢失
- 删除（Delete/按钮/右键）：确认弹窗、删除后集合与摘要刷新

兼容性测试：

- 旧版配置（无 id/useCount/lastUsedTimeUtc）启动后不崩溃，且能自动补齐
- 配置文件包含注释/尾随逗号：可读取（JsonOptions 已允许）
- 配置损坏（写入非法 JSON）启动后不崩溃，且会生成 .corrupt 备份

性能测试（在上限 20 个预设场景）：

- 打开窗口、输入搜索、切换排序/视图操作应无卡顿
