## 根因修复（控制逻辑）
- 消除后台循环跨线程访问 WPF 控件：把多段式循环里对速度模式的获取从 `GetVelocityModeSelection()` 改为只读配置（`_configStore.Get().VelocityMode`），并据此选择 `MaxKmh`。
- 让 `GetVelocityModeSelection()` 变为“仅 UI 线程可读控件”的安全实现：若非 UI 线程则直接回退到配置值，避免再次触发 `InvalidOperationException`。
- 同步修复诊断路径：`Handling.Diagnostics.cs` 中计算速度比值/模式的逻辑同样不要读取 `VelocityModeComboBox.SelectedIndex`，统一走配置值，保证诊断不会在后台更新时崩。

## 稳健性增强（防止“看似开启但无效”）
- 在多段式循环捕获到异常时，将“最后一次异常类型/时间/次数”写入可读的诊断字段（用于 UI 展示），并在简易诊断里将 `state=Bad` 的原因细分为 `UI线程访问/手柄读失败/写入失败/注入失活`。
- 对 `TryReadSpeedKmh` 失败的场景增加降级策略：维持上一次有效 `uSpeed` 或启用低通滤波的 `uSpeedEma`，避免速度偶发读失败导致曲线退回起步段、体感突变。

## 算法与参数优化（确保三段平滑切换与体感一致）
- 为 `uSpeed` 增加轻量平滑：`uSpeedEma = lerp(uSpeedEma, uSpeed, alpha)`（如 alpha≈0.15），并限制每 tick 最大变化量，减少段边界抖动。
- 调整写入节流策略：把 `|ΔuSpeed|>=0.01` 的触发与 100ms 定时写结合为“最小写入间隔 + 速度变化触发”，并允许在段边界附近更频繁写入（提升切换顺滑）。
- 复核默认参数合理性：重点检查 `VelocityAMaxKmh=260`（可能过低导致很早进入高速段）与各模式 `StageEnd/TargetFrac` 的默认值，给出推荐默认值区间与解释。

## 验证与回归（多轮验证测试）
- 使用现有速度诊断面板做白盒验证：确认 `Multi` 模式下 `loop=Y write=Y state=Ok`，`multiExceptions=0`，`HookActive=Y CrcOk=Y`，`pressed=Y` 时 `VelEnabled` 持续为 1。
- 分段平滑性验证：在固定 RT 输入（例如 30%/60%/100%）下，记录随车速上升的 `calcBoost` 与 `memData.Boost`，确认在 `stage1End/stage2End` 附近无明显阶跃/回跳。
- 性能与稳定性验证：观察 5 分钟巡航中 `writeFails` 率、`applyHz` 估算是否稳定、CPU 占用是否无异常增幅。
