## 现象分解（速度页面为何会“全挂”）
- 速度页面（Handling 的速度区）三种模式（Fixed/Linear/MultiStage）以及相关限速/强度参数，本质都依赖同一条“基础注入链路”：先建立 LocalPlayer detour（CarCheats.CheatLocalPlayer），再对 detour 数据区写入 VelEnabled/VelBoost/VelLimit 等字段。
- 因此只要以下任一关键点失败，就会表现为“速度页面所有组件都失效”：
  - AoB 特征码扫描找不到 Hook 点（_localPlayerHookAddress==0）
  - CRC 绕过补丁未生效（Bypass.DisableCrcChecks -> IsCrcPatchApplied=false）
  - detour 写入被回滚/覆盖（IsLocalPlayerHookActive=false，循环里会不断尝试重贴）

## 签名验证机制梳理（工具内部如何判定“签名失效”）
- AoB 扫描（功能签名）：通过固定字节序列（signature）在游戏主模块内存范围内扫描，找到第一个匹配地址；找不到即判定失效并提示。
- detour 完整性校验（运行中验证）：对 hook 点读回前 5 字节，与“应当写入的 JMP detour”逐字节比较；不一致则认为 hook 失活，会尝试重新写回。
- CRC 补丁状态：Bypass 扫描并 patch 一段校验逻辑，内部用 m_applied 记录是否已应用；速度/刹车等注入前置条件会依赖它。

## 可能触发“之前正常、现在失效”的原因清单（按概率/可验证性排序）
- 环境/权限变化：未以管理员运行导致无法稳定读取/写入关键内存页；或 Windows 安全策略/杀软拦截 ReadProcessMemory/WriteProcessMemory。
- 进程目标变化：附加到的 PID 变了（同名进程/残留进程/崩溃重启），导致扫描落在错误的内存空间。
- 二进制实际被改动但版本号未变：Steam 验证修复、OnlineFix DLL 更新、外部注入（Overlay/Mod/Reshade 等）改变了目标指令序列。
- 工具文件不完整/版本不一致：只替换了 exe 或部分 dll，导致 Memory.dll / Reloaded.Memory.Sigscan 版本不匹配或被杀软隔离；很多异常在 UI 事件里被吞掉，看起来像“签名找不到”。
- hook 被第三方覆盖：其它修改器/注入器在同一位置打了 hook，导致 detour 字节被改写；诊断里会表现为 HookActive 反复 false。

## 文件备份与“丢失/损坏”排查点（当前仓库已知机制）
- 配置备份：Handling 自动配置如果 JSON 解析失败会自动把原文件移动/复制为 .corrupt.<时间戳>.bak，然后重置为默认配置。
- 程序文件备份：仓库代码中未发现对 exe/dll 的自动备份/回滚逻辑；因此如果安装目录文件被删/被隔离，通常只能通过重新解压/重装恢复。

## 恢复方案建议（不改代码的用户侧操作）
- 先看“是否真实附加”：主界面 Attached=On、PID 稳定；必要时先关闭游戏再开，避免 PID 快速变化。
- 以管理员运行工具；临时关闭/放行杀软对工具目录与游戏进程的拦截（尤其是内存访问拦截/隔离）。
- 移除所有注入/覆盖层：关闭 ReShade/RTSS/MSI Afterburner/各类 Overlay、其它修改器；仅保留游戏与本工具。
- 验证/修复游戏文件；如果是 OnlineFix 版本，确认 OnlineFix64.dll 未在最近被替换。
- 彻底重装工具：从官方 Release 重新下载完整包，删除旧目录后重新解压，避免“只复制了 exe”。
- 重置配置：删除 %LocalAppData%\MA_FH5Trainer\ 下的 handling 自动配置（会自动再生成）；如存在 .corrupt.*.bak 说明曾发生配置损坏。

## 代码侧排查与增强计划（需要你确认后我再动手实现）
- 增强 AoB 扫描诊断：记录并显示扫描范围（模块名、Base、Size）、ReadProcessMemory 失败率、命中的地址数量、耗时。
- 将速度页面关键依赖显式化：在 Handling 诊断文本里增加“LocalPlayerSigFound/BypassSigFound/DetourCreated/HookActive/CrcPatchOk”的分项状态与最后一次失败原因。
- 增加“自检/修复”按钮：一键执行 DisableCrcChecks + CheatLocalPlayer + 重贴 detour，并把每一步结果写入诊断。
- 增加“文件完整性自检”（可选）：启动时校验关键依赖文件是否存在/版本是否匹配，发现缺失给出明确提示（避免异常被吞掉）。

## 验证与回归标准
- 速度区开关打开后：LocalPlayerHookDetourAddress>0，HookActive=true，CrcPatchOk=true。
- 触发 RT 后：VelEnabled/VelBoost/VelLimit 写入成功计数上升，诊断里车速读取正常（TryReadSpeedKmh=true）。
- 不影响其它模块：刹车增强/轮速跳跃等同样依赖 detour 的功能也能稳定工作。
