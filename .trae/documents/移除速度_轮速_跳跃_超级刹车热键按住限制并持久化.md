## 目标
- 速度控制、轮速调整、跳跃修改、超级刹车不再依赖“预热键+按住触发”，开启后自动保持生效。
- 自动开启状态持久化保存，游戏重启（Trainer 重新附加）后依然自动生效。

## 现状定位
- 四项功能当前仅在热键回调里写入 Enabled=1：Handling.xaml.cs（VelocityCallback/WheelspeedCallback/JumpHackCallback/BrakeHackCallback）。
- 热键系统要求 Modifier 匹配并在按住主键时循环回调：HotkeysManager.CheckHotkeys。
- Enabled/Boost/Limit 对应 detour 数据区偏移：CarCheatsOffsets（CarCheats.cs）。

## 实现方案
### 1) 为四项功能加入“自动触发运行器”
- 在 Handling.xaml.cs 内为每个功能增加一个后台循环（Task + CancellationTokenSource）。
- ToggleSwitch 打开时：启动对应循环；关闭时：取消循环并确保写一次 Enabled=0（立即停止）。
- 循环逻辑：当 LocalPlayerHookDetourAddress 可用时，按固定间隔写 Enabled=1；地址不可用时节流等待。
- 对跳跃保留较长间隔（例如 1000ms）；对刹车/速度/轮速设置合理下限间隔避免 CPU 空转。

### 2) 跨“游戏重启/重新附加”的自恢复
- 循环内部判断地址/附加状态：未附加或地址为 0 时不写内存，仅等待并重试。
- 在需要时（且频率受限）调用 CheatLocalPlayer() 重新建立 detour；一旦重新附加成功，自动继续写入，无需玩家操作。
- 页面卸载/窗口关闭时统一取消所有循环，避免后台残留。

### 3) 持久化保存“自动开启状态”
- 新增一个轻量配置管理器（仿 ThemeManager 的 JSON 落盘方式）：
  - 路径：%LocalAppData%\\MA_FH5Trainer\\handling-auto.json
  - 字段：VelocityAutoOn / WheelspeedAutoOn / JumpAutoOn / BrakeAutoOn
- Handling 页面初始化时读取配置并恢复 UI 开关；用户切换开关时实时保存。

### 4) UI 文案（推荐）
- 将 Handling.xaml 中四个开关文案从“（热键）”改为“（自动）”，避免误导。
- 热键系统与热键保存机制保留不破坏；但这四项默认不再依赖热键触发。
