## 需求拆解

* 你要“线性加速”作为**新增按钮/开关**，不要改动原来的“速度（RT自动）”，这样方便在同一套强度参数下对比测试。因为之前按钮可以绑定RT阈值(%)，接下来实现的功能不需要绑定这个

## 最终 UI 形态（Handling 页面）

* 保留现有开关：`速度（RT自动）`（行为恢复为原始：固定 Boost/Limit + 按住 RT 触发）。

* 新增一个开关：`线性加速（RT自动）`（行为：Boost 随 RT 力度线性变化）。

* 两个开关**互斥**：打开其中一个会自动关闭另一个，避免两套写入逻辑互相覆盖。

* “强度/限制”数值框继续复用你现有的 `VelocityStrength(1-10)` / `VelocityLimit`，不用新增额外参数；这样你调同一组强度时，只需要切换按钮即可对比固定/线性。

## 行为定义（算法细节）

### A) 旧功能：速度（RT自动）= 固定强度

* RT 超阈值时：每个 tick 写 `VelEnabled=1`。

* `VelBoost` 固定为：`1 + strength/1000`（与当前 UI 强度的尺度一致）。

* `VelLimit` 固定为当前 `VelocityLimit`。

* 松开 RT：写 `VelEnabled=0`。

### B) 新功能：线性加速（RT自动）= 随 RT 力度线性

* 设：

  * `strength = VelocityStrength (1..10)`

  * `maxDelta = strength/1000`

  * `thresholdByte = RT阈值(%) -> 0..255`

  * `u = clamp((RT - thresholdByte)/(255 - thresholdByte), 0..1)`（过阈值后从 0 线性到 1）

* RT 超阈值时：

  * `VelBoost = 1 + maxDelta * u`

  * `VelLimit` 使用当前 `VelocityLimit`

  * `VelEnabled=1`

* 松开 RT：写 `VelEnabled=0`。

## “温和注入”策略（不追求 60Hz）

* 两个模式统一使用较温和节拍：默认 **33ms（约 30Hz）**。

* 为减少写入量：

  * `VelEnabled` 仍按 tick 写 1（保证一次性消费时也能持续生效）。

  * `VelBoost/VelLimit` 采用“变化阈值/低频刷新”：例如 u 变化 >= 0.01 或每 100ms 才写一次。

## 配置持久化

* 保持原字段：`VelocityAutoOn` 控制旧模式。

* 新增字段：`VelocityLinearAutoOn` 控制线性模式。

* 启动加载时：若两者都为 true，按互斥规则只保留线性模式为 true（旧模式自动置 false），避免冲突。
