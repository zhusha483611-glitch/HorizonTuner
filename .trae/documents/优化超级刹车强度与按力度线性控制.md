## 你问的点：可以新加 UI 组件和按钮吗？
- 可以。本次会在 Handling 页面直接新增一套独立的 UI 控件（开关 + 强度滑条/数值框），不复用“超级刹车”的那组控件。

## 目标
- 保留现有“超级刹车（LT触发）”完整功能与 UI。
- 新增一个更温和的“刹车增强（LT触发）”功能，并在 UI 上可见、可调。

## UI 设计（新增组件）
- 在 [Handling.xaml](../../MA_FH5Trainer/MA_FH5Trainer/Views/SubPages/SelfVehicle/Handling.xaml) 的“超级刹车”下面新增一个 Border（和现有风格一致），包含：
  - `mah:ToggleSwitch`：标题“刹车增强（LT触发）”
  - `Slider + NumericUpDown`：强度（0~100，默认 20）
  - 可选：一行小字说明“比超级刹车弱，按 LT 力度动态增强”

## 逻辑实现
- 在 [Handling.xaml.cs](../../MA_FH5Trainer/MA_FH5Trainer/Views/SubPages/SelfVehicle/Handling.xaml.cs) 新增：
  - 一组新的 CTS 与自动循环 `s_brakeAssistAutoCts`
  - 新的 Toggled/ValueChanged 事件处理
  - 一个“力度→boost”的计算：`boost = 1 - k * (LT/255)`，k 由 UI 强度映射到很小范围，保证更温和。
  - 循环在 LT 超过阈值时才写 Enabled=1；松开写 0。

## 与超级刹车共存策略
- 两者共用同一套 detour 参数（BrakeHackEnabled/BrakeHackBoost），因此实现上会做“互斥”避免抢写：
  - 开启刹车增强时自动关闭超级刹车；开启超级刹车时自动关闭刹车增强。
- UI 上仍同时保留两个开关，你按需选择。

## 持久化
- 在 [HandlingAutoConfigManager.cs](../../MA_FH5Trainer/MA_FH5Trainer/Resources/Config/HandlingAutoConfigManager.cs) 扩展 JSON：
  - `BrakeAssistAutoOn`（新开关状态）
  - `BrakeAssistStrength`（新强度）
- 保留旧字段不变，向后兼容。

## 验证
- 编译通过。
- 游戏内验证：
  - 打开“刹车增强”：轻踩 LT 轻微减速，深踩更明显，但整体弱于超级刹车。
  - 打开“超级刹车”：仍按原 StopSlider 行为生效。
  - 两者互斥生效，不会叠加导致异常减速。
