## 现象定位（为什么现在像线性）
- 当前多段曲线本质仍是“分段幂函数插值”，但默认参数（尤其是 stage3Gamma≈1.3、stage3权重占比偏大）会让 0.7–1.0 的段看起来接近线性爬升，体感会更像线性加速。
- 另外调试信息目前输出了大量数值（boost/speed/uSpeed/limit/…），会干扰判断；你希望把这些“值”移除，仅保留关键状态。

## 优化目标
- **多段式手感明确**：低速更有“起步冲劲”，中速平滑接力，高速明显衰减/趋于平台（而不是继续像线性往上爬）。
- **上限可控**：最高 boost 仍由“强度”决定，不改动你现有的强度语义。
- **诊断可读**：默认只显示“是否在工作 + 为什么不工作”，隐藏大部分数值；需要时可切到“高级诊断”。

## 实施方案（会改代码）
### 1) 重做 Multi 曲线为“目标点插值”而非简单分配权重
- 新增三个“目标 boost 点”：
  - `B0 = 1.0`
  - `B1 = 1 + maxDelta * f1`（uSpeed 到 Stage1End 时达到的倍率）
  - `B2 = 1 + maxDelta * f2`（uSpeed 到 Stage2End 时达到的倍率）
  - `B3 = 1 + maxDelta`（最终上限，仍 clamp 到 2.0）
- 每一段用 `SmoothStep`（或 `EaseInOut`）在相邻目标点之间插值，gamma 只影响段内曲线弯曲：
  - 0–Stage1End：快速抬升（更有“冲劲”）
  - Stage1End–Stage2End：较平滑
  - Stage2End–1.0：明显放缓趋于平台
- 这样“分段感”来自目标点和插值形状，而不是权重分配，体感会更明显。

### 2) 增加可调的分段边界与目标点比例（保留现有 UI 参数的兼容）
- 在 config 中新增：
  - `VelocityStage1End`（默认 0.25~0.30）
  - `VelocityStage2End`（默认 0.60~0.70）
  - `VelocityStage1TargetFrac`（f1，默认 0.65~0.80）
  - `VelocityStage2TargetFrac`（f2，默认 0.90~0.98）
- 兼容策略：若新字段缺失（旧配置），使用现有 `stage1Scale/stage2Scale/stage3Scale` 推导默认 f1/f2 与边界。

### 3) 重新调 A/S1/S2 预设，让“多段感”默认就明显
- 预设方向（示例，最终以实测再微调）：
  - **A 车**：更强的起步（f1 高），更早进入衰减（stage2End 较低）
  - **S1 车**：起步和中段均衡（f1 中高，f2 接近 1）
  - **S2 车**：中高速更保守（f1 中等，stage3 逼近平台更明显）
- 同时给出一组“推荐 gamma”：
  - stage1Gamma 取 0.8–1.2（更早抬升）
  - stage2Gamma 取 1.2–1.8
  - stage3Gamma 取 2.0–3.0（高速更慢更像平台）

### 4) 精简调试信息（按你说的“把调试信息的值除去了”）
- 增加一个配置/开关：`ShowAdvancedVelocityDiagnostics`（默认 false）。
- **默认诊断（无数值版）**只输出：
  - 模式（Off/Fixed/Linear/Multi）
  - HookActive/CrcOk
  - pressed（Y/N）
  - mem(en=0/1)
  - applied/s（只保留是否为 0 或 >0，可显示“0”或“>0”）
  - multiTick/s、multiWrite/s、multiStateFail/s、multiEx/s
- **高级诊断（保留数值）**才输出 boost、speed、uSpeed、limit、localPlayer 指针等。

## 验收标准（你跑一圈就知道）
- Multi 模式下，低速（uSpeed<Stage1End）会明显更“窜”，中段平顺，高速（uSpeed>Stage2End）明显趋于平台。
- 默认诊断不再显示一长串数值，仅显示工作状态；切到高级诊断才显示详细值。
