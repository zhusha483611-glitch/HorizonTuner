## 目标
- 去掉“多段式加速模块”三段曲线（S1/S2/S3）的参数范围限制，让 Gamma 与比例（Scale）不再被硬性夹在当前区间。

## 现状定位（限制来自两层）
- **UI 控件层**：Handling.xaml 的 6 个 NumericUpDown 通过 Minimum/Maximum 限制输入范围（S1/S2/S3 的 Gamma、比例%）。
- **逻辑层**：Handling.xaml.cs 在 4 个位置用 Math.Clamp 再次限制（加载配置、ValueChanged 写回配置、缓存 UI 值、计算 boost 时）。

## 修改方案
### 1) 放开 UI 输入范围
- 修改 [Handling.xaml](file:///d:/AI/MA_FH5Trainer_CN-main/MA_FH5Trainer/MA_FH5Trainer/Views/SubPages/SelfVehicle/Handling.xaml) 中以下控件：
  - VelStage1Gamma / VelStage2Gamma / VelStage3Gamma
  - VelStage1Scale / VelStage2Scale / VelStage3Scale
- **移除** Minimum/Maximum 属性，让 MahApps NumericUpDown 使用默认范围（Minimum=double.MinValue，Maximum=double.MaxValue），从 UI 层不再卡死输入。

### 2) 去掉配置加载时的 Clamp
- 修改 [Handling_OnLoaded](file:///d:/AI/MA_FH5Trainer_CN-main/MA_FH5Trainer/MA_FH5Trainer/Views/SubPages/SelfVehicle/Handling.xaml.cs#L151-L203)：
  - 把 `_velocityStage*Gamma/_velocityStage*Scale = Math.Clamp(...)` 改为“仅做有限值保护”：
    - 如果值为 NaN/Infinity，则回退到默认值（3.0/1.8/1.3 和 0.3/0.5/0.7）。
    - 否则原样接受配置文件里的值（即允许超范围）。

### 3) 去掉 ValueChanged 写回配置时的 Clamp
- 修改 [VelStage*Gamma_OnValueChanged / VelStage*Scale_OnValueChanged](file:///d:/AI/MA_FH5Trainer_CN-main/MA_FH5Trainer/MA_FH5Trainer/Views/SubPages/SelfVehicle/Handling.xaml.cs#L647-L837)：
  - Gamma：删除 Math.Clamp，直接保存新值（仅过滤 NaN/Infinity）。
  - Scale：删除 Math.Clamp，仍保持“百分比→比例”的 `/100d` 转换后直接保存（仅过滤 NaN/Infinity）。
  - 这样 UI 输入什么，配置就持久化什么。

### 4) 去掉缓存 UI 值时的 Clamp
- 修改 [UpdateCachedUiValues](file:///d:/AI/MA_FH5Trainer_CN-main/MA_FH5Trainer/MA_FH5Trainer/Views/SubPages/SelfVehicle/Handling.xaml.cs#L2110-L2130)：
  - 删除对 `_velocityStage*Gamma/_velocityStage*Scale` 的 Math.Clamp，仅做有限值保护与默认回退。

### 5) 去掉多段式曲线计算时的参数 Clamp
- 修改 [CalculateVelocityMultiStageBoost](file:///d:/AI/MA_FH5Trainer_CN-main/MA_FH5Trainer/MA_FH5Trainer/Views/SubPages/SelfVehicle/Handling.xaml.cs#L1449-L1491)：
  - `stage*Gamma` 与 `stage*Scale` 不再 Math.Clamp，改为直接使用缓存值（仅 NaN/Infinity 回退）。
  - 保留对 `u` 的边界处理（必要时继续 clamp 到 0..1），避免异常输入导致 Pow 产生 NaN。
  - 末尾 `boost` 的 1..2 clamp、`maxDelta` 的 0..0.2 clamp **先保持不动**（它们不属于“曲线参数限制”，且对稳定性更关键）。如你也希望放开最终强度上限，我可以在下一步把这两处也一并解开。

## 实现细节（避免重复代码）
- 在 Handling.xaml.cs 内新增一个小的私有静态方法（无注释）：
  - `SanitizeDouble(value, fallback)`：当 value 不是有限数时回退 fallback。
- 所有原先用 Math.Clamp 的多段式参数赋值点统一改用该方法。

## 验证方式
- 本地编译 `MA_FH5Trainer.sln`（Debug/Release 均跑一次）确保无警告/错误（项目 TreatWarningsAsErrors=true）。
- 运行后手动验证：
  - 多段式 6 个控件可输入超出原范围的值并能保存（重启后仍保持）。
  - 打开多段式自动加速时，参数改变会即时影响手感且不崩溃。

## 影响评估
- 正向：解除“卡死范围”后可做更激进/更细腻的三段曲线调校。
- 风险：极端参数可能导致加速曲线变得很不线性；但由于最终 boost 仍 clamp 到 1..2，稳定性风险较低。
