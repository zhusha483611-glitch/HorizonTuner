## 已确认的问题（基于文档+代码交叉验证）
1. **预设下拉框无法稳定停留在 S1/S2/A**：选择预设会程序化写入各段 Gamma/Scale，但这些控件的 `ValueChanged` 又会强制把模式切回“自定义”，导致用户刚选的预设被覆盖并写回配置。
   - 代码位置：Handling.xaml.cs 中 `VelocityModeComboBox_OnSelectionChanged` 与 `VelStage*Gamma/Scale_OnValueChanged`。
2. **多段式自动循环健壮性不足**：`RunVelocityMultiStageAutoAsync` 缺少 `EnsureLocalPlayerDetourAsync()` 以及 try/catch，异常可能直接让循环任务退出；同时 detour 失效时不易自愈（线性/轮速循环已有该保障）。
   - 代码位置：Handling.xaml.cs 中 `RunVelocityMultiStageAutoAsync` 对比 `RunVelocityLinearAutoAsync`。
3. **技术文档中的 JSON 示例与实际序列化不一致**：`VelocityPreset` 使用 `JsonPropertyName("name"/"stage1Gamma"...)`，因此配置文件里预设项字段名是小写 camelCase，而文档示例写的是 `Name/Stage1Gamma/...`。
   - 代码位置：VelocityPreset.cs（JsonPropertyName）与 handlingautoconfigmanager.cs（JsonSerializer 未设置命名策略）。
4. **对话框界面可读性/一致性**：InputWindow 的 TextBox 使用 AccentBase 作为背景，容易造成对比度不足；两个窗口目前继承 `Window`，与主窗口的 MahApps MetroWindow 风格不一致。

## 修复与优化计划（实现顺序）
### 1) 修复“选择预设自动回到自定义”
- 在 Handling.xaml.cs 引入一个 UI 更新保护开关（例如 `_suppressVelocityStageUiEvents`）。
- 在 `VelocityModeComboBox_OnSelectionChanged`、`ApplyCustomPreset` 等“批量写控件值”的代码块中开启保护，写入完毕后关闭保护。
- 在所有 `VelStage*Gamma/Scale_OnValueChanged` 处理器中：
  - 若处于保护状态则直接返回（不写配置、不切模式）。
  - 仅在“用户手动改值”时才切换到 Custom 并持久化。

### 2) 增强多段式自动循环的稳定性与一致性
- 让 `RunVelocityMultiStageAutoAsync` 对齐线性/轮速循环的做法：
  - 每个 tick 先调用 `EnsureLocalPlayerDetourAsync(token)`。
  - 包裹 try/catch 防止异常导致循环任务退出。
- 保持现有降频写入策略（u 变化阈值/100ms）不变，仅补齐“自愈与异常隔离”。

### 3) 预设保存/管理的错误修复（按文档“已知问题”落地最关键两项）
- 保存预设时：
  - 名称去重（同名自动追加后缀）。
  - 可选：限制最大数量（例如 20），超出给出提示并拒绝新增。
- 重命名时：同样做名称去重与空白检查。

### 4) 优化预设管理窗口与输入窗口的显示效果
- 将 `PresetManagerWindow` 与 `InputWindow` 统一改为 `mah:MetroWindow`（并同步修改 code-behind 继承类）。
- InputWindow：TextBox 改为使用 MahApps 的标准 TextBox 背景/边框资源（避免 AccentBase 造成可读性问题），并补齐窗口背景/前景资源，保证深色/浅色主题下都清晰。
- PresetManagerWindow：
  - 给 ListView/列宽做更合理的伸缩（或加入 Margin/对齐），减少拥挤。
  - 按钮默认样式更克制（至少保证“应用/确定”为主按钮，其它为次按钮），提升层次感。

### 5) 修正文档中的不一致与错误示例
- 更新 docs/多段式加速预设系统技术文档.md 中的配置 JSON 示例：
  - 预设字段名改为 `name/stage1Gamma/.../createdTime`。
  - 同步说明 `VelocityMode` 为 enum 数值存储。
- 对文档中与现状不一致的窗口属性（如 ResizeMode/Height）做轻量校正。

## 验证方式（实现完成后执行）
- 进行 `dotnet build`（Debug/Release 至少一项）确保编译通过。
- 关键手动验证点：
  - 选择 S1/S2/A 后 ComboBox 不再自动跳回 Custom；改动任意 Gamma/Scale 才会切到 Custom。
  - 多段式循环在 detour 失效/短暂异常情况下不“永久失效”（循环仍在跑，恢复后能继续生效）。
  - 保存/重命名同名预设会自动去重；达到上限时给出明确提示。
  - 两个对话框在深色/浅色主题下文字与输入框对比度正常。
