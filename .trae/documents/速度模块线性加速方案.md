## 目标效果（速度模块）
- RT 轻按：小幅提速；RT 深按：更明显提速；松开 RT：立即停止。
- 最大提速强度不改变你当前手感上限：仍然由“速度强度”决定（例如强度=3 时，满按 RT 的 boost 上限仍接近你现在的固定值）。

## 方案总览
### 1) 线性加速公式（用现有“速度强度”作为最大值）
- 设：
  - `strength = VelocityStrength.Value`（1..10）
  - `maxDelta = strength / 1000`（保持你当前强度尺度不变）
  - `t = RT/255`（0..1）
  - `t0 = 阈值(%) / 100`（你现有阈值控件）
  - `u = clamp((t - t0) / (1 - t0), 0..1)`
- 每次触发时写入：
  - `VelBoost = 1 + maxDelta * u`  （线性随 RT 力度变化）
  - `VelLimit` 继续使用你现有的固定限速值（不新增 UI）
  - `VelEnabled = 1`（见下面“脉冲/频率”策略）

### 2) 温和注入频率（把“写入次数”降到更舒适）
- 把速度自动循环 tick 改为 **33ms（约 30Hz）** 或 **50ms（约 20Hz）**（默认给 33ms，体感更连贯）。
- 进一步减少写入量：
  - `VelBoost/VelLimit`：只有当 `u` 变化超过很小阈值（例如 0.01）或每 100ms 才写一次。
  - `VelEnabled`：按住 RT 期间按 tick 写一次 `1`（把它当“脉冲”喂给 detour），松开写 `0`。

### 3) 去除调试信息（你要求的清理）
- 删除/移除：速度tick/秒、写入/秒、错误计数、Detour 地址等状态栏拼接内容。
- 保留最基础的：`手柄已连接(index=...) RT=... LT=...`（或你想要的最简文本）。

### 4) 保留必要的后台线程/缓存（但不再展示调试）
- 即使不追求 60Hz，也仍建议保留“后台线程循环 + 缓存 UI 值”这一点：
  - 防止 UI 线程波动把注入频率压到几秒一次。
  - 防止后台线程直接读取 WPF 控件导致跨线程异常。
- 这部分是稳定性需要，不属于调试输出。
